## 3. 무기와 성장

무기는 활 1종. 발사 주기·데미지·투사체 수·관통·사거리는 전부 `WEAPON_BOW`.
**사거리 내 적이 없으면 발사하지 않는다** — "적을 끌어들이는" 위치 판단이 남는다.

### 3-A. 조준 규칙 `WEAPON_BOW.AIM` — 전역 규칙 1개 (시련 분기 아님)

**문제(playtest 1회차 실측, 2026-08-08)**: 키클롭스 시련이 200판 중 보스 처치 **0건**,
보스 피해량 중앙값 **0.0%**(최대 11.8%). `AIM='nearest'`인데 grunt/brute가 거의 항상 보스보다
가깝고, 보스 속도 16은 플레이어 60에서 계속 뒤처진다. 이 시련은 `goal:1, wBossKill:1` —
**보스 처치가 유일한 클리어 조건**이라 클리어율이 구조적으로 0%다. 화력을 올려도 움직이지 않는다.
동시에 이건 **GDD §5가 이미 적어 둔 의도("잡몹 압력을 낮춰 보스에 화력을 쏟게 한다")를
구현할 장치가 애초에 없었다**는 뜻이다.

**규칙 (`AIM = 'bossFirstThenNearest'`)**

```
후보 = 사거리(WEAPON_BOW.RANGE) 안의 살아 있는 적
후보가 0개        → 발사하지 않는다. 쿨다운도 흐르지 않는다.  (기존과 동일)
후보에 type='boss'가 있으면 → 그중 최근접을 조준한다.
그 외              → 후보 중 최근접을 조준한다.              (기존과 동일)
```

- 분기 기준은 **`EnemyRuntime.type`(적 종류)이지 시련 id가 아니다.** → §8-2(시련 id 분기 0개) 유지.
- 연꽃·이타카는 `bossSpawnSec = 999 > timeLimitSec 180`이라 보스가 **원리적으로 등장하지 않는다.**
  즉 이 규칙은 3종 중 **2종에서 증명 가능한 무동작(no-op)**이고, 키클롭스에만 영향을 준다.
- 발사 빈도·투사체 수·확산·관통은 하나도 바뀌지 않는다. **바뀌는 것은 "누구를 겨누는가" 하나뿐이다.**
- 한 판에 보스는 1기뿐(`bossSpawnSec`으로만 등장)이지만, 규칙은 "boss 중 최근접"으로 적어
  보스가 2기 이상이 되어도 정의가 무너지지 않게 한다.
- 서사적 근거: **활은 가장 큰 위협을 노린다.** 오디세우스가 구혼자들 사이에서 안티노오스를
  먼저 쏘는 장면과 같은 규칙이다. 예외 규칙이 아니라 설명 가능한 규칙이라 플레이어가 학습할 수 있다.

**대안을 버린 이유** — B2(보스 속도 인상)는 D8(적 속도 상한 1.35×, 최대 46 < 플레이어 60,
"도주는 끝까지 가능")을 뒤집는다. B3(키클롭스 goal 변경)은 D1·§5의 "보스 = 체력 많은 적 1기"를
없앤다. B4(사거리 인상)는 §1의 "사거리 140 = 화면 폭 29%" 근거를 무너뜨리고, **최근접 우선인
한 보스는 여전히 후순위라 문제 자체를 안 푼다.** B1만이 다른 수치 근거를 하나도 건드리지 않는다.

**확정됨 (2026-08-08, 2회차-B 실측 후. D39).** `WEAPON_BOW.AIM`의 기본값이 이제
`'bossFirstThenNearest'`이며 잠정값이 아니다.

| 지표(키클롭스) | 2회차-A (`nearest`) | 2회차-B (`bossFirstThenNearest`) | 판정 |
|---|---|---|---|
| 보스 HP 피해 중앙값 | 11.8% | **29.1%** | 규칙이 의도대로 동작 |
| 보스 처치 | 6 / 200 | **13 / 200** | 〃 |
| 레벨업 중앙값 | 5 | **4** | 대가(아래) |
| 초당 처치 | 0.846 | **0.772** | 대가(아래) |
| 동시 최대 적 p95 | 49 | **54** | 합격 ≤90 유지 |
| 연꽃·이타카 8개 지표 | — | **바이트 단위 동일** | D28-ⓑ 무동작 실증 |

- **감시하기로 했던 대가가 실제로 나타났다**: 화살이 보스에 묶여 잡몹 처치와 XP 회수가 줄었다
  (레벨업 5→4, 초당 처치 0.846→0.772). 동시 최대 적 p95는 합격 범위 안이다.
  **이 값들은 이제 3회차의 기준선에 포함된다** — 되돌리는 것이 아니라 기준선으로 삼는다.
- **그런데도 키클롭스 클리어율은 0.065(합격 0.35의 1/5)다.** 중앙값 29.1%는
  "화력이 보스에 못 닿는다"가 아니라 **"닿아도 700HP를 다 못 깎는다"**는 뜻이다.
  `ENEMIES.boss.HP` 주석의 계산(DPS 18.2 → 70발 → 38.5초, 등장 30초 + 38.5 = 68.5초)은
  **"보스에만 100% 명중"을 전제**했는데, 실측 도주 비율 63% / 사거리 밖 틱 7.6%로 그 전제가 깨졌다.
  → **남은 원인은 `ENEMIES.boss.HP` 하나**이며 조정은 4회차다(§6-A). **3회차에 같이 바꾸지 않는다.**

### 레벨업 3택 구성 규칙
- 3택은 **화력 1 + 생존 1 + 유틸 1**을 각 카테고리에서 뽑는다.
- 해당 카테고리에 만렙 아닌 후보가 없으면 남은 카테고리에서 보충한다.
- → "3개가 전부 공격력 +%"인 화면이 **구조적으로 나올 수 없다.** 이게 이 게임의 유일한 플레이어 결정을 지키는 장치다.

| 카테고리 | 항목 |
|---|---|
| 화력 | 청동 촉(데미지) / 쌍둥이 화살(투사체+1) / 빠른 손(주기-15%) / 관통 화살(관통+1) |
| 생존 | 가죽 갑옷(최대HP+20) / 아테나의 가호(무적+0.2s) / 넥타르(즉시 40% 회복, 무제한 반복) |
| 유틸 | 헤르메스의 샌들(이동+12%) / 먼눈(흡수반경+40%) |

### 3-B. 3택의 세부 규칙 (문서에 없어서 tech가 임의로 정했던 것 — 이제 여기가 원본)

1. **`HIDE_ARMOR`(가죽 갑옷)는 최대HP 증가분(+20)만큼 현재HP도 즉시 회복한다.**
   근거: 전투 중에 최대HP만 올라가면 "HP 바의 빈칸이 늘어날 뿐" 그 순간에는 아무 일도 안 일어난다.
   생존 카테고리의 선택지가 **지금 죽지 않게 해 주지 않으면** 화력 선택지와 경쟁이 성립하지 않는다.
   넥타르(즉시 40% 회복)와의 차이는 유지된다 — 갑옷은 +20 고정·상한 4회, 넥타르는 비율·무제한.
2. **3택 대기 중에는 게임 시간이 멈춘다**(`RunState.pendingChoice`가 있는 동안 `stepRun`이 시간을 진행시키지 않는다).
   **§9-5의 시련 시작 배너는 반대로 멈추지 않는다.** 두 규칙이 다른 이유는 하나다 —
   **정지는 sim이 아는 것만 허용한다.** 3택 정지는 sim 내부 상태라 헤드리스 측정과 브라우저가 같은
   경과 시간을 보지만, 배너는 렌더 전용이라 sim이 모르고, 배너로 멈추면 §6 측정이 무효가 된다.
   (측정 영향: 봇은 3택을 즉시 고르므로 sim의 지표는 이 규칙과 무관하다. 브라우저 체감에만 영향.)

## 4. 스폰 압력 = 유일한 긴장의 출처

10초를 1**스텝**으로, 스텝마다 ① 스폰 간격 ×0.92 ② 적 HP +12% ③ 적 속도 +3%(상한 1.35×).
적 속도 상한 1.35×에서도 가장 빠른 적(46)이 플레이어(60)보다 느리다 — **도주는 끝까지 가능하다.**
난이도는 "못 도망침"이 아니라 "**도망칠 공간이 없어짐**"에서 나온다.

## 5. 시련 3종 — 차이는 `TRIALS` 데이터 행 3개뿐

**클리어 판정은 3종 공통 단일 함수다. 시련별 `if` 분기가 0개여야 한다.**

```
progress = 경과초 * wTime + 잡몹처치수 * wKill + 보스처치수 * wBossKill
클리어 ⇔ progress >= goal        패배 ⇔ HP<=0 또는 경과초 > timeLimitSec(180)
```

| 시련 | goal | wTime/wKill/wBoss | 보스 | 스폰총량 | 조합(grunt/brute) | 간격× | HP× | 속도× |
|---|---|---|---|---|---|---|---|---|
| 키클롭스의 동굴 | 1 | 0/0/1 | 30초 | ∞ | 0.7 / 0.3 | 1.25 | 1.00 | 1.00 |
| 연꽃 먹는 자들의 해안 | 90 | 1/0/0 | 없음 | ∞ | 0.3 / 0.7 | 0.85 | 1.15 | 0.85 |
| 이타카의 홀 | 108 | 0/1/0 | 없음 | **108** | 1.0 / 0.0 | 0.75 | 0.90 | 1.10 |

- **키클롭스의 동굴** — 보스는 "체력 많은 적 1기". 고유 패턴 없음. 잡몹 압력을 낮춰 보스에 화력을 쏟게 한다.
- **연꽃 먹는 자들의 해안** — 느리고 단단한 다수. 화력 3택을 안 고르면 화면이 메워진다.
- **이타카의 홀** — 고정 108기 섬멸. 유일하게 실제로 추격당하는 조합.

오디세이아다움은 **시련 이름 + `tagline` 한 줄까지다.** 그 이상은 WON'T.

## 6. 목표 지표 (합격선) — `TARGET_METRICS` 및 `playtest.md`와 동일값

측정 조건: **시련별 200회, 시드 고정, 봇 정책 = §7.** 시련별로 따로 측정한다(합산 금지).

| 지표 | 합격 구간 |
|---|---|
| 시련별 클리어율 | **0.35 ~ 0.70** |
| 사망한 판의 생존시간 중앙값 ÷ 90초 | **0.45 ~ 0.85** |
| 30초 이전 사망 비율 | **≤ 0.15** |
| 판당 레벨업 횟수 중앙값 | **8 ~ 14** |
| 판 평균 초당 처치 수 | **1.0 ~ 4.0** |
| 동시 최대 적 수 p95 | **≤ 90** |
| 도달 난이도 스텝(10초=1) 중앙값 | **5 ~ 9** |
| 클리어한 판의 클리어 시각 중앙값 | **≤ 117초** |

**한 판 목표 길이 = 90초**(`TRIAL_TARGET_SEC`). 근거: 제출물 2번이 30~60초 영상이라 한 판이 90초면
편집 없이도 클리어 장면까지 담기고, 심사자가 링크를 눌러 한 판을 끝까지 볼 수 있다.

"30초 이전 사망"의 **30초는 `TARGET_METRICS.EARLY_DEATH_SEC`**다(= 3스텝 = 목표 판 길이의 1/3).
합격선이 아니라 지표의 정의이며, 값은 1회차 그대로다.

### 6-A. 튜닝 회차 계획 — 한 회차에 한 축만 (1회차 반려 대응, 2026-08-08)

1회차 결과: 클리어율 0.000/0.055/0.030, 레벨업 중앙값 2/1/2, 초당 처치 0.535/0.308/0.712 (전부 미달).
**합격선은 한 줄도 고치지 않는다.** 측정값이 안 나온다고 합격선을 내리는 건 자기기만이다.

| 회차 | 바꾸는 것 | 왜 이 순서인가 |
|---|---|---|

### 9-1. 미술 양식 — 고대 그리스 **적색상(red-figure) 도기화**

어두운 바탕 + 밝은 황토색 인물. 흑색상(밝은 바탕 + 검은 실루엣)을 쓰지 않는 이유는
`SPAWN.MAX_ALIVE = 90`이기 때문이다. 밝은 바탕 위의 검은 실루엣 90개는 한 덩어리로 뭉친다.

**색 규칙(이게 90마리 식별의 유일한 장치다): 플레이어·내가 낸 것 = 차가운 색(청록·백금) /
적 = 따뜻한 색(적갈·주황·흙자주).** 색상환 반대편에 배치한다.

**논리 해상도 480×270과 카메라 줌은 동결**이다(D14). 이 문서 수치 근거의 절반이 화면 대비
비율이라(사거리 140 = 폭의 29%, 보스 반경 14 = 높이의 5%) 바꾸면 밸런스를 전부 다시 재야 한다.

### 9-2. 생성 에셋 6개 (이게 전부다 — §2 상한)

| 우선 | 파일(배포 산출물) | 생성 캔버스 → 배포 규격 | 내용 | 표시 크기 |
|---|---|---|---|---|
| ① | `public/sprites/player.png` | 1024×1024 투명 → **투명 PNG** | 오디세우스(활 + 원뿔 필로스 모자), 청록·백금 | **18px** |
| ② | `public/sprites/grunt.png` | 512×512 투명 → **투명 PNG** | 구혼자. 마르고 빠름. 주황·적갈 | **14px** |
| ③ | `public/assets/arena.jpg` | 1920×1080 불투명 → **960×540 JPEG(알파 없음)** | **아레나 전체 1장**(타일 아님). `ARENA` 960×540과 1:1이라 이음매가 없다. 어둡고 저대비 | **1.0배** |
| ④ | `public/sprites/boss.png` | 1024×1024 투명 → **투명 PNG** | 폴리페모스. 뼈색 + 단안 호박색 발광 | **40px** |
| ⑤ | `public/audio/bgm.mp3` | — | 루프 BGM 1곡, 60초 목표(최대 90초) | 음량 0.5 |
| ⑥ | `public/sprites/brute.png` | 512×512 투명 → **투명 PNG** | 로토파고이. 넓고 둔중. 흙적·자주 | **22px** |

**포맷 규칙 — "투명 PNG"는 스프라이트 4종에만 적용된다. 배경 1장은 명시적 예외로 불투명 JPEG다.**
(D25) 근거 둘: ⓐ 배경은 아레나 전체를 덮으므로 **투명 픽셀이 원리적으로 없다.** ⓑ 사진 계열 석재
텍스처라 무손실 PNG가 노이즈를 그대로 저장한다 — 같은 원본 실측으로 PNG 720.8KB vs JPEG 26.7KB(27배).
**이 예외는 배경 1장뿐이다.** 스프라이트를 JPEG로 바꾸면 알파가 사라져 배경 위에 사각형이 뜬다.

**배포 규격이 960×540인 이유(= `ARENA_IMAGE_SCALE` 1.0):** 백킹스토어가 480×270 고정(D14)이고
카메라 줌이 1이라 **1 월드 px = 1 캔버스 px**다. 게다가 렌더러가 `pixelArt: true`(NEAREST)라
1920 원본을 0.5배로 깔면 2×2 블록 중 1픽셀만 표본되고 **나머지 3/4는 화면에 절대 도달하지 않는다.**
용량만 4배이고 화질 이득이 0이다. 축소는 오프라인 Lanczos로 끝낸다 — 런타임 점표본보다 면적 평균이 낫다.

**이 표는 「새로 생성한 것」만 센다.** 같은 원본에서 다시 뽑은 **파생 파일은 §9-8·`ASSET_CREDITS.md` §1-D**에 있고
`ASSETS.MAX_DERIVED_IMAGE_FILES`(2)로 따로 통제한다(D35). 현재 파생 1장: `public/sprites/title-hero.png`.

- **뒤 순번이 끝내 도착하지 않아도 게임은 완성 상태다**(§8-20 폴백). tech는 에셋을 기다리지 않는다.
- 화살·경험치 오브·3택 아이콘은 **생성하지 않는다.** 12px 이하에서 손그림과 코드 도형이 구분되지 않는다.
- 표시 크기 근거: 90마리가 전부 화면에 들어온 최악의 경우 점유율. grunt 14px = 화면의 13.6%.
- **배경 화질에 문제가 보이면 되돌리는 순서는 하나뿐이다**: 960×540을 유지한 채 ① JPEG 품질을 올린다
  → ② 그래도 안 되면 960×540 **무손실 PNG**(720.8KB)로 간다. `MAX_IMAGE_TOTAL_KB`(800)는
  ②까지 들어가도록 잡은 값이다. **해상도를 1920으로 되돌리는 선택지는 없다**(위 문단 이유).

### 9-3. 시련 3종의 시각 구분 = `TrialDef.bgTint` **한 필드**

배경 이미지는 3종 공통 1장이고, 시련마다 곱연산 틴트만 다르다.
시련별 배경 이미지를 만들면 에셋이 3배가 되고 씬에 시련 id 분기가 생겨 §8-2를 깬다.

| 시련 | bgTint | 성격 |
|---|---|---|
| 키클롭스의 동굴 | `0x8090b8` | 차가운 청회색. 가장 어둡다(≈0.62) — 보스의 호박색 단안이 유일한 발광원이 된다 |
| 연꽃 먹는 자들의 해안 | `0xc8c090` | 바랜 모래빛. 가장 밝다(≈0.76) — 흙적·자주 brute가 배경에서 떨어진다 |
| 이타카의 홀 | `0xc08870` | 횃불빛 적동색(≈0.72). 주황 grunt와 색이 가까우므로 채도를 낮춘다 |

각 채널 **≥ 0x70**을 지킨다. 그 아래는 배경이 검게 뭉쳐 적 90마리의 실루엣 경계가 사라진다.

### 9-4. 3택 아이콘 = 코드 도형 배지 (PNG 아님)

카테고리 3색 정사각 배지 + 스택 수 숫자. `VISUAL.COLOR.CAT_FIRE/LIFE/UTIL`이 `UPGRADE_CATEGORIES`와 1:1.
아이콘 9장을 그리면 에셋이 6→15개가 되고, 그 9장이 12px에서 서로 구분되지도 않는다.
**3택 카드는 이름(한글 텍스트)이 의미를 나른다.** 배지는 카테고리와 스택 수만 나른다.

### 9-5. HUD 배치 (480×270 기준. 화면 좌표 고정, 카메라를 따라가지 않는다)

```
 ┌───────────────────────────────────────────────────────┐
 │ [HP바 6,6 84x6]        01:12 / 3:00        처치 37 →│  y 0–12
 │ [Lv/XP 6,15 84x4]   [ 진행도바 140x5 43/108 ]        │  y 12–20
 │                     ▮▮▮▮▯▯▯▯▯ STEP 4                 │  y 20–26
 │                                                       │
 │                  (플레이 영역 y 30–250)               │
 │                                                       │
 │                                        BGM OFF →     │  y 246
 │ [배지][배지][배지] …                          fps 60 →│  y 252–264
 └───────────────────────────────────────────────────────┘
```

- **진행도 바는 `trialProgress()` 반환값을 그대로 그린다.** HUD가 진행도를 따로 계산하면 §8-3
  ("클리어 판정은 단일 함수 1곳") 위반이다. 표시값 = `trialProgress(...) / goal`.
- **"웨이브 타이머"는 이 게임에 없다.** 웨이브 개념 자체가 없고(§4) 압력은 10초=1스텝 곡선뿐이다.
  존재하지 않는 개념을 화면에 띄우지 않는다 → **난이도 스텝 pip + 경과/제한시간**이 그 자리를 대신한다.
- 스텝 pip는 9칸(= 목표 판 길이 90초). 9스텝을 넘으면 칸은 가득 찬 채 옆 숫자만 올라간다.
- 본문 폰트 최소 **8px**. 6px 한글은 정수배 스케일에서도 획(1px)이 소실된다(카피바라 실측).
  **폰트 파일은 도입하지 않는다** — 시스템 sans-serif만 쓴다.
- 시련 시작 배너는 `name` + `tagline`을 2.5초 표시 후 0.5초 페이드. **게임 시간은 배너 중에도 흐른다.**
  일시정지를 넣으면 배너를 모르는 sim과 브라우저의 경과 시간이 달라져 §6 측정이 무효가 된다.

### 9-5-A. 레벨업 3택 화면 (현재 "스타일 없는 클릭 목록" — HUD 단계에서 이 규격으로 교체한다)

이 게임의 **유일한 플레이어 결정**이 뜨는 화면이다. 현재 구현은 최소 클릭 목록이고, 그건 임시다.
아래가 교체 목표 규격이며 **여기가 원본**이다.

```
 ┌───────────────────────────────────────────────────────┐
 │              (게임 화면이 어둡게 깔린다)              │
 │                    LEVEL  7                           │  y 60
 │  ┌──────────┐   ┌──────────┐   ┌──────────┐          │
 │  │ ▪ 화력   │   │ ▪ 생존   │   │ ▪ 유틸   │          │  y 96
 │  │ 쌍둥이   │   │ 가죽     │   │ 헤르메스 │          │
 │  │ 화살     │   │ 갑옷     │   │ 의 샌들  │          │
 │  │   Lv.2   │   │   Lv.1   │   │   Lv.3   │          │
 │  └──────────┘   └──────────┘   └──────────┘          │  y 174
 └───────────────────────────────────────────────────────┘
```

- 카드 3장, **가로 중앙 정렬**. 수치는 `HUD.CHOICE_CARD`(tech가 balance.ts에서 읽는다).
- 각 카드에 **카테고리 배지(§9-4의 코드 도형, `VISUAL.COLOR.CAT_*`) + 한글 이름 + 다음 스택 수**.
  **의미는 한글 이름 텍스트가 나른다**(D16). 설명 문장·수치 툴팁은 만들지 않는다 —
  9종 × 설명문은 폰트 8px에서 읽히지도 않고 번역 유지 비용만 는다.
- **카테고리 배지 3색이 서로 다르다는 것 자체가 §3의 "3택은 성격이 다르다"를 화면에서 증명한다.**
  이게 배지를 넣는 유일한 이유다. 장식이 아니다.
- **입력은 마우스 클릭 1종.** 키보드 단축키는 만들지 않는다 — §2의 조작 축 상한(이동 1축)을 지키고,
  "클릭도 되고 키도 되는" 이중 입력은 QA 경우의 수를 2배로 만든다.
- 배경은 게임 화면 위에 반투명 암막(`HUD.CHOICE_DIM_ALPHA`). 완전 불투명으로 덮지 않는다 —
  플레이어가 **지금 얼마나 포위됐는지 보면서** 화력/생존을 고르는 게 이 결정의 내용이다.
- **이 화면이 떠 있는 동안 게임 시간은 멈춘다**(§3-B-2). 시련 시작 배너와 반대다.

브라우저 자동재생 차단 때문에 **타이틀의 첫 입력에서 재생을 시작**한다.

### 9-7. 이 축의 대가 (스코프는 순증가하지 않는다)

에셋·HUD를 넣는 대신 **밸런스 튜닝 왕복을 제한**한다. 상한을 넘으면 `playtest` 측정만 하고
수치를 동결하며, 남은 시간은 제출물 4종에 쓴다.

**상한 2회 → 3회로 개정 (2026-08-08, D37).** 원래 근거는 *"에셋을 스코프에 넣는 대가로 시간이
모자랄 것"*이었는데 **그 전제가 실측으로 깨졌다** — 렌더 축 구현에 4시간 30분을 배정했으나
`tech`가 **38분**에 끝냈다. 예산의 근거가 시간이었으므로 시간이 남으면 예산도 남는다.
늘린 1회를 무엇에 쓰는지도 미리 못박는다: **3회차 = `XP_CURVE.GROWTH`, 4회차 = `ENEMIES.boss.HP`**
(§6-A). **동결 시점은 4회차 직후**이며, 5회차는 없다.

### 9-8. 타이틀 화면 (2026-08-08 추가 — D35)

**왜 이 화면만 규격을 따로 두는가**: 심사자가 링크를 눌러 **처음 보는 화면**이고, 동시에
제출물 2번(30~60초 영상)의 **첫 프레임**이다. 지금은 검은 배경 + 흰 글씨뿐이라 첫인상이 비어 있다.
**새 에셋을 만들지 않고** 기존 `arena.jpg` + `player.png`의 파생 1장으로만 채운다.

수치 원본은 `HUD.TITLE`(레이아웃·암막)과 `ASSETS.PATHS.titleHero`(파일 경로)다.

```
 ┌───────────────────────────────────────────────────────┐
 │        (arena.jpg를 1:1로 깔고 그 위에 검정 암막)     │
 │              오디세이 서바이버즈                       │  y 16  18px
 │        ↑↓ 로 시련 선택, Enter/클릭으로 시작            │  y 31   9px
 │                    ┌────────┐                         │
 │                    │ 오디세 │  128×128                │  y 40–168
 │                    │  우스  │  (중심 240,104)         │
 │                    └────────┘                         │
 │                 키클롭스의 동굴                        │  y 182 14px
 │        외눈의 거인이 입구를 막았다. …                  │  y 194  8px
 │              연꽃 먹는 자들의 해안                     │  y 212
 │              이타카의 홀                               │  y 242
 └───────────────────────────────────────────────────────┘
```

**규칙**

1. **배경** — `ASSETS.PATHS.arena`를 `VISUAL.ARENA_IMAGE_SCALE`(1.0) 그대로, 화면 중앙 정렬로 1장 깐다.
   즉 960×540 원본의 **가운데 480×270만 보인다.** 축소하지 않는 이유는 D25와 같다 —
   `pixelArt: true`(NEAREST)에서 0.5배 축소는 3/4 픽셀을 버리는 점표본이다.
2. **틴트를 걸지 않는다.** `TrialDef.bgTint`는 **시련의 것**이고 타이틀에는 시련이 없다.
   타이틀에서 틴트를 고르려면 "어느 시련 색인가"라는 결정이 생기고, 그건 §8-2(시련 id 분기 0개)로 가는 길이다.
3. **암막** — 배경 위에 검정 `HUD.TITLE.DIM_ALPHA`(0.75)를 덮는다. 게임 화면은 암막이 **0**,
   3택 화면은 0.65, 타이틀은 0.75다. → **세 화면의 밝기가 서로 다르다**는 것이 화면 구분의 전부다.
4. **히어로** — `ASSETS.PATHS.titleHero`를 `HUD.TITLE.HERO_PX`(128) 정사각으로 중심 (240,104)에 그린다.
   원본이 128px이라 **배율 1.0 = 재표본 0**이다. 확대·축소·회전·애니메이션 없음.
5. **시련 3종 목록과 조작 안내는 기능이 그대로다.** ↑↓ 선택 / Enter·Space·클릭 시작, 선택 항목은
   `VISUAL.COLOR.XP_ORB`, 비선택은 `COLOR.TEXT`. 바뀌는 것은 **좌표뿐이며 그 좌표는 `HUD.TITLE`에 있다**
   (128px 히어로가 들어가면서 세로 배치가 재조정됐다. 씬에 좌표 리터럴이 남으면 §8-6 위반).
6. **폴백 (§8-20)** — `title-hero.png`가 없으면 **그 자리를 비운다.** 대체 도형을 그리지 않는다
   (128px 청록 원은 없는 것보다 나쁘다). `arena.jpg`가 없으면 `VISUAL.COLOR.ARENA_FALLBACK` 단색으로
   대체하고 암막은 그대로 적용한다. **어느 경우에도 콘솔 에러 0건이고, 나머지 요소의 좌표는 절대 좌표라
   한 픽셀도 움직이지 않는다.** 레이아웃이 에셋 유무에 따라 흔들리면 그건 폴백이 아니라 두 번째 레이아웃이다.
